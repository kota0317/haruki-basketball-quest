# Parent and learner sync

This implementation is under review. The learner and parent authenticate with separate email/password accounts. The parent generates a 256-bit random, 15-minute, single-use code; the learner consents by entering it while signed in. Only a hash is stored. Database functions validate authenticated callers and token shape and atomically consume the code. Private SECURITY DEFINER functions are invoked through narrow authenticated SECURITY INVOKER wrappers; the private table and links are not directly writable by clients. Function owner privileges are intentional and must remain audited. Revocation is currently administrator-only.

RLS restricts learning-event reads to their learner and explicitly linked parents, and inserts to the learner. No event update or delete privilege is granted to client roles. Study-plan select, insert and update are limited to the learner and linked parents; deleting from the UI sets active=false. Neither role can create a parent link through direct table writes. A student can report their own time; the backend cannot guarantee its truthfulness.

The existing localStorage object is preserved. After the learner explicitly binds the current device, a pre-migration snapshot is retained under a separate key. Each old and new row receives a persistent event UUID and enters a durable local outbox before any upload. Offline errors preserve the queue; retries reuse UUIDs. On duplicate ID, server contents are compared before acknowledging. Remote records are merged by ID. The queue is account-bound; other accounts cannot upload it. Legacy backup files without IDs cannot reliably be deduplicated across independent imports. Backups that include cloud binding cannot be restored over a bound device through the UI. The app still uses localStorage, which has quota and same-device multi-tab race limitations.

In the dedicated project, synthetic transaction-scoped SQL tests passed: pairing, replay denial, linked parent read, parent plan create/edit and disable, parent event insert denial, stranger denial and duplicate event rejection. Security advisor reports an informational RLS-without-policy finding for the private invites table; it is intentional and no direct privileges are granted. Mocked frontend tests cover offline queue, lost-response retries and duplicate reconciliation. Real user signup, email delivery, full browser UI and Android two-device verification are outstanding.
