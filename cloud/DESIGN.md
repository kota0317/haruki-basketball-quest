# Parent and learner sync — draft, not deployed

The current `haruki-quest-prototype-v1` localStorage object contains sessions, answers and matches without stable IDs. Do not clear, overwrite or migrate it until the user has a verified backup and a working authenticated backend. The proposed event store uses immutable UUIDs, learner ownership and a separately provisioned parent link. The parent receives SELECT only for explicitly linked learner records; other users receive no rows. The learner may insert their own events. Neither role can update or delete events through this API. The current student can submit self-reported study times; database permissions cannot guarantee that the student's own records are truthful.

Pairing is intentionally not implemented as a guessable code or by self-declared client metadata. A trusted admin should create the relationship only after verifying both distinct auth user IDs; no administrative credential goes in browser code. A convenient secure pairing flow needs separate design and adversarial tests.

Before upload, assign each local row a UUID and persist the complete mapping and a device/install identifier transactionally in IndexedDB; maintain an outbox with stable IDs across retry, app restart and network loss. Upload immutable records with insert, resolve a duplicate by comparing the server's existing record, and mark delivered only after confirmation. Never silently discard errors or clear local data. Distinct identical study entries must remain distinct. Design backup/restore to preserve identifiers; legacy JSON imports without identifiers require a preview and explicit conflict handling rather than pretending duplicates can always be distinguished. Bind the local queue to the confirmed learner account and never upload it after switching accounts without an explicit migration confirmation.

Parent dashboard derives daily totals in Asia/Tokyo, first-attempt category accuracy, due reviews and streaks from events. Show empty mock-exam data as unavailable; current app does not implement mock exams. Timestamps for legacy session rows have only a local date, not a trustworthy time: preserve the original date and mark its precision rather than inventing a timestamp.

Required integration tests before publication: child insert/select, parent linked SELECT, parent INSERT/UPDATE/DELETE denied for child, stranger/anon denied, account-switch isolation, duplicate retry, concurrent writes, offline restart, legacy migration and restore, expired sessions, first-login on separate Android devices. Test under actual JWTs, not service-role credentials. The SQL has been applied to a new dedicated project. Synthetic transaction-scoped RLS checks passed for linked-parent reads and plan edits, and denial of child event writes and unrelated-user reads. No actual account, client integration, synchronization or device tests have been completed. Parent-plan editing is permitted; existing event history remains insert-only for the learner.
